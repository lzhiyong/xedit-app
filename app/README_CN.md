## 使用

### 编辑

- **撤销重做跨会话保留**：重新打开文件时，如果文件内容没变（按 SHA-256 判断），恢复光标和撤销历史；没保存的修改可以用重做找回。
- **代码折叠**：按 tree-sitter 的 `folds` 查询，没有查询时按缩进。
- **已打开的文件**：点击工具栏上的应用标题，列出所有打开的文件，当前文件高亮并滚动到中间；点击切换到对应标签。打开了几十个文件时比滚动标签栏方便。长按标签有关闭、关闭其他、关闭全部、分享。
- **跳转到行**：输入 `行号` 或 `行号:列号`，可预览目标行。
- **选择浮条**：剪切、复制、粘贴、全选、搜索；⋮ 中还有分享、能处理选中文字的其他应用（翻译、朗读等）、注释、格式化、文档大纲。
- **注释**：选中整行时用行注释（`//`、`#`、`--`，加在缩进最少的位置），选中行内一部分或语言没有行注释时用块注释；已经是注释则取消。整个操作是一次撤销。
- **外部修改**：当前文档被其他应用修改时，可以重新加载，或继续编辑并在保存时覆盖；文件被删除时，可以保留内容（保存时重新创建）或关闭。

### 全屏

手机上软键盘弹出后，工具栏和标签栏会占掉一大块。全屏时它们收成一条细栏（与标签栏一样高），状态栏也隐藏（从顶部下滑可临时呼出），编辑区多出约 90dp。

- **细栏**：当前文件名、它在已打开文件中的位置（如 `3/12`）、未保存的圆点、忙碌时的转圈；点文件名列出所有已打开的文件。右侧是撤销、重做、保存、⋮（工具栏的完整菜单）和退出全屏。
- **何时进入**：**设置 → 编辑器 → 全屏模式**：仅从菜单进入（默认）/ 软键盘弹出时 / 始终。也可以用菜单中的**全屏**或快捷键 `F11` 随时切换。
- **退出**：细栏上的退出按钮、菜单或返回键。在「软键盘弹出时」模式下手动退出后，下次弹出键盘时会再次进入。
- 弹出菜单、文件列表或面板时保持当前状态，不会因为键盘收起而退出。

### 补全

- **何时弹出**：输入服务器的触发字符（`.`、`->`、`::`）立即请求，输入单词时短暂停顿后请求；之后继续输入在本地过滤。没有语言服务器时，对文本中的单词做模糊补全。
- **选中一项后**：替换当前单词、展开代码片段、执行附加编辑（如插入 `#include`）。服务器只给出函数名时，按签名生成参数占位 `foo(a, b)`。光标后已经存在的闭合字符会被覆盖而不是重复插入。整个过程是一次撤销。
- **片段跳转**：Tab 跳到下一个参数，最后跳到 `)` 之后；Shift+Tab（或长按符号栏的 Tab）返回。
- **路径补全**：输入 `./`、`../`、引号中的路径或 `/sdcard/...` 这样的绝对路径时，列出该处的文件。
- 实体键盘：方向键选择，Enter 或 Tab 确认，Esc 关闭。

### 控制台

类似 VS Code 的底部面板，三页：**输出**（按频道显示应用、语言服务器、构建的日志）、**错误**（已打开文档的诊断和最近一次构建的错误，点击跳转）、**构建**（运行命令，并从输出中识别 gcc、clang、Python 的报错）。

工具栏上的运行按钮「编译并运行」当前文件，长按可修改命令和运行参数。命令在哪里运行、在哪个目录运行，见[工具链](TOOLCHAIN_CN.md#编译并运行)。

### AI 编程助手

**菜单 → 开发工具 → AI 编程助手** 让大模型在当前文件所在的项目里工作：读取、搜索、修改项目里的文件，还能用应用内的工具链在项目里运行命令，循环往复，直到任务完成。

- **设置（⚙）**：服务商、API 地址、模型和 API 密钥。**Anthropic（Claude）** 使用 Anthropic 的 Messages API；**OpenAI 兼容接口** 支持任何提供 OpenAI chat completions 和工具调用的接口（OpenAI、DeepSeek、OpenRouter、通义千问、本机 Ollama `http://127.0.0.1:11434/v1` 等），地址填 `/chat/completions` 之前的部分。所选模型必须支持工具调用。每个服务商各自保存地址、模型和密钥；密钥用 Android Keystore 加密保存在本机，只会发送到对应的地址。
- **能做什么**：列出、读取、搜索工作区根目录下的文件（直接执行）；写入文件、按精确文本替换修改文件；在根目录运行 shell 命令（最长 15 分钟，输出过长会截断）。不能访问根目录以外的文件。默认每次修改文件、每次运行命令前都会先显示 diff 或命令，等你选择**允许**、**本次对话都允许**或**拒绝**。在 ⚙ 里可以改成修改文件不问，或者全部不问。
- **工作区**是当前文件所在的项目，查找方式和「编译并运行」相同（含构建文件的目录，见[工具链](TOOLCHAIN_CN.md#编译并运行)）。模型还会知道当前打开的文件、光标所在行和选中的文本。
- 助手修改过的文件，如果在标签页中打开且没有未保存的修改，会自动重新读取；有未保存的修改时，会像其他应用修改了文件那样询问你。卡片上的**打开**可以直接打开该文件。
- **代码块和输出只读查看**：回答里的代码块、读取文件和运行命令的结果都显示在应用自己的编辑器（`CodeEditorView`）里，按语言语法高亮，最多显示 20 行，可以左右滑动；头部的**复制**复制整段，**展开**（或点一下代码）打开全屏查看。全屏查看带行号，可以长按选择，浮条里只有**复制**和**全选**，不能编辑，也不会弹出键盘；大段文本在后台排版，和编辑器打开大文件一样流畅。写入、修改或读取过的文件，卡片上的**查看**用同样的方式只读打开（最大 32 MB）。
- **停止**会立即结束本轮（请求、命令、等待中的确认）。关闭面板不会停止：对话在后台继续，再次打开时还在，直到关闭这个界面。**新对话**（+）重新开始。

### 外观

**设置 → 编辑器** 中可以设置应用主题（浅色、深色、纯黑、动态取色）、高亮主题（内置 astrodark、astrolight，可导入导出）、字体（内置 JetBrains Mono、Source Code Pro，可导入）、字号和 Tab 宽度。自己创建主题见[配置](CONFIG_CN.md#高亮主题)。

高亮资源下载支持断点续传，只在资源包的 ETag 变化时重新下载；状态见**设置 → 语法高亮资源**。

## 限制

- 高亮资源下载完成前，文件不显示语法高亮。
- 应用不附带语言服务器。没有文件路径的文档（如网盘提供的文件）不会发给语言服务器。
- 没有「所有文件访问」权限时，路径补全和 `.editorconfig` 等项目样式文件只能通过文件树中**添加文件夹**打开的目录读取；单独**打开文件**的文档没有可用目录。
- 外部修改只检查当前显示的文档，依据文档提供方给出的修改时间和大小；两者都不提供的提供方无法检测。
- 文件按 UTF-8 读写（保留 BOM）。
- AI 编程助手的对话只在编辑界面存在期间保留，也不会自动裁剪：对话太长可能超出模型的上下文长度（可以开新对话）。它的命令只用应用内的工具链运行（不走 Termux），项目在共享存储中时需要「所有文件访问」权限才能运行命令。

## 开发须知

**包结构**（`x.editor.app` 下）：`activity`（编辑界面）、`controller`（文件树、标签页、搜索、语言服务器 `LspController`）、`highlight`（tree-sitter 高亮）、`lsp`（服务器配置与连接、补全辅助）、`console`、`toolchain`、`config`（开发工具面板）、`service`（文档读写与会话）、`view`（`CodeEditorView`，接入了 tree-sitter 的 `EditorView`）。其余包名即用途。

**语法高亮为什么不卡**：

- 主线程从不执行 tree-sitter 查询。文本按 2048 字符分块，在工作线程上用语法树副本和文本快照计算高亮，主线程只拼接已算好的块。
- 编辑时高亮块随文本平移，新输入的字符立即沿用相邻颜色；下次解析后只重新查询有变化的块。
- 已经着色的行永远不会被纯文本替换（`RowCache`），所以不闪烁。
- 解析、新旧树比较、缩进线和折叠的计算都在工作线程上。
- 查询谓词在 C++ 中判断（见 [treesitter](../treesitter/README_CN.md)）；不可能产生高亮的注释不交给注释语法解析（`sqlite3.c` 中跳过了 92%）。
- 效果：在开发设备上滚动编辑 `sqlite3.c`，卡顿帧比例从 31% 降到 4%，90 分位帧耗时从 89 ms 降到 18 ms。

**打开与保存文档**：同一时间只加载一个文档，切换时先等上一个加载完全停止；只有完整加载过的文档才会被写回，因此一个文件的内容不可能写进另一个文件；保存依次执行，写回失败时文档保持打开、修改不丢。编辑会话和文件内容的 SHA-256 一起保存，哈希一致才恢复。

**开发工具面板**（菜单 → 开发工具下的 6 个面板）共用一套骨架和手势；每个面板同一时间只执行一个会改动内容的操作（`OperationGate`）。新建条目使用 `assets/templates/` 下的模板，占位符统一写成 `{{名字}}`。

**忙碌圆点动画**（`view/BusyDotsDrawable`，工具链面板"更新"按钮工作时的图标）可以用在任何能放 Drawable 的地方。它由四个子动画（`BusyMotion`）组成：`SquareSwap`（正方形两条对角线依次交换）、`TriangleWalk`（三个点沿三角形转一圈）、`RowWave`（一排三个点依次跳起）和 `Pulse`（圆点聚成一个再分开）。每个子动画都可以单独循环；`BusyDotsSpec` 可以把几个按顺序组合起来，形状不同的两个之间，圆点会先聚拢再分裂成下一个形状（`morph`）。`speed` 统一缩放所有时长。

```kotlin
val dots = BusyDotsDrawable.ofDp(context)                                   // 完整循环
val wave = BusyDotsDrawable.ofDp(context, spec = BusyDotsSpec.of(BusyMotion.RowWave()))
val mix = BusyDotsDrawable.ofDp(context, 24f, BusyDotsSpec.of(
    BusyMotion.SquareSwap(rounds = 2), BusyMotion.Pulse(), speed = 1.5f))

button.setBusyDots(busy, dots, R.drawable.ic_update)   // MaterialButton：忙时显示圆点，结束后换回图标
imageView.setBusyDots(busy, wave)                      // ImageView：忙时显示圆点，结束后换回原来的图
textView.setBusyDotsAtStart(busy, dots)                // TextView：忙时在文字前面显示圆点（AI 助手的“思考中”）
menuItem.icon = mix; mix.start()                       // 也可以像普通 Animatable 一样手动控制
```

圆点跟随所在视图的着色；视图不可见时自动暂停；运行中可以直接替换 `spec`。

**AI 编程助手**（`agent/`）分几层。`LlmProvider` 是访问模型的唯一接口：一个请求（系统提示词、由文本/工具调用/工具结果组成的消息、以 JSON Schema 描述的工具）以 `LlmEvent` 流式返回，最后整体返回 `LlmReply`；`AnthropicProvider` 和 `OpenAiProvider` 负责转换成各自 API 的 JSON，并把流式事件拼回完整回答（`SseParser`，以及基于 OkHttp 的 `LlmHttp`；取消协程即取消请求）。要接入其他服务商，新写一个实现该接口的类，并在 `AgentSettings.ProviderKind` 里加一种。`AgentTools` 是工具（`AgentTool`：描述、风险等级——读取/写入/命令、摘要、给用户看的预览、执行），作用在 `Workspace` 上；`Workspace` 保证所有路径都在根目录内，按路径或通过用户的 SAF 授权读写（`LocalFiles.writeText`）。`AgentSession` 负责循环（模型 → 工具 → 结果 → 模型，每轮最多 `MAX_ROUNDS` 次请求），按设置通过面板征求用户同意，并通过 `AgentHost`（EditorActivity）和编辑器交互。文本处理（精确替换、glob、截断）、流解析和请求体在不依赖 Android 的单元测试中覆盖（`src/test/.../agent/`）。

**迷宫动画**（`view/MazeView`，资源状态顶部卡片的背景）像在玩游戏：小球看得见出口（边缘一个轻微呼吸的圆环），但不知道路，以固定速度匀速滚过去（每格 300ms，前进和后退一样，中途不停顿），每经过一个格子（后退时也一样）留下一个圆点。每个圆点各自慢慢淡出，小球再走 5 格时就完全消失，所以身后只有一小段轨迹：画第 6 个圆点时，第 1 个已经看不见了（`DOT_LIFE_STEPS`）。到岔路口挑一条没走过的路，多数时候挑朝出口方向的那条；走进死胡同就掉头，退回到上一个还有路没试过的岔口（也就是边走边做深度优先搜索）。到达出口时生成新的随机迷宫（Kruskal 算法，另外随机多打通少量墙，所以会有环路），从小球位置缓慢向外扩散替换旧迷宫，新出口选在中等距离的边缘格子。点击迷宫，小球移到点击位置所在的格子，忘掉之前走过的路，从那里重新找出口。它只是背景，不是主角：所有元素都用卡片的文字颜色、以很低的透明度绘制（小球也是，不用强调色）；在 `setQuietViews` 指定的视图（卡片的图标、标题、副标题和数字）下面，透明度再降到三分之一，保证文字清晰易读；深色主题下卡片本身也比容器色略暗一些。各种时长、尺寸和透明度都是类末尾的常量。视图不可见时暂停；系统关闭动画时静止不动。实现时只参考了 Vector 状态卡片的截图和录屏，没有阅读或使用 Vector（GPL）的任何代码。

**资源命名**：`<种类>_<功能>_<部分>`，如 `dialog_goto_line`、`item_extra_key`、`ic_content_copy`、`bg_pref_card_top`；字符串以功能开头（`search_`、`lsp_`、`toolchain_`）。`strings.xml` 和 `values-zh/strings.xml` 分节顺序一致，新增或删除字符串时两边同时修改。

**测试**：`./gradlew :app:testDebugUnitTest`，覆盖补全触发、文本单词补全、构建输出识别、运行命令、悬停 Markdown、服务器配置文件、格式化规则、快捷键文件（含旧版本升级）、工具链规则等纯逻辑部分；界面和 Termux 交互依赖手动验证。
